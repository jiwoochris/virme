# 책 디자인: 표지 사례에서 장르 문법을 세고, 그 문법으로 책 한 권을 짭니다

이야기(`/story` 결과)와 서사 오브젝트를 받아 신국판(152×225mm) 책 한 권을 PNG 와 PDF 로 만듭니다. 앞표지, 속표지,
차례, 장마다 장 시작 면과 삽화가 든 본문, 판권, 뒤표지까지 들어갑니다. 디자인 값은 손으로 정하지 않습니다. 실제 책 표지
206장을 장르별로 재고 라벨을 붙여 센 분포에서 뽑습니다. 그 가운데 30장은 사람이 라벨을 검수했습니다.

## 여기서 "배운다"는 뜻

모델을 새로 학습하거나 미세 조정하지 않습니다. 11월 7일 시연까지 5주 안에 검증할 수 있는 방식으로, 다음 두 가지를 합니다.

1. **사례 검색**: 참고 표지마다 측정값과 라벨을 붙여 두고, 책을 만들 때 장르와 분위기가 맞는 표지 6장을 찾습니다.
2. **디자인 문법 추출**: 장르마다 레이아웃 원형·제목 위치·서체·그림 양식·분위기·명도·색의 분포를 셉니다
   (`grammar.json`). 브리프는 이 분포의 절반과 찾은 6장의 표 절반을 더한 점수에서 값을 뽑습니다.

그래서 결과를 설명할 수 있습니다. 브리프 파일(`brief.json`)에 칸마다 후보 점수와 뽑을 확률, 출처("참고 표지 분포에서
뽑음", "기본값", "사람이 고름"), 참고한 표지의 제목·출처 URL·사람 검수 여부, 분위기를 정한 이유가 그대로 남습니다.
대신 새로운 디자인을 발명하지는 않습니다. 참고 표지에 없는 문법은 나오지 않고, 그림의 품질은 이미지 생성 모델에 달려 있습니다.

## 돌려 보기

```bash
cd core
export OPENROUTER_API_KEY=sk-or-v1-...      # 없으면 라벨·소개글은 건너뛰고, 그림은 절차적 그림으로 그린다

M="uv run python -m virtueme_core.book"
$M collect --per-genre 30      # Open Library 에서 장르마다 30장 (한국어판 절반) → $VIRTUEME_DATA/book_refs/
$M annotate                    # 측정값 + 비전 라벨 → references.json (키가 없으면 측정값만, --no-llm 도 같음)
$M review --n 30 --seed 1      # 사람이 라벨을 검수하는 연락 시트 HTML (아래 「라벨 검수」)
$M review --apply label-corrections.json
$M grammar                     # 장르별 분포 → grammar.json, 아래 표 출력

S=virtueme_core/book/samples
$M brief  --genre 미스터리 --narrative "$S/seoyeon_narratives.json#콩이" --story $S/mystery.txt
$M render --genre 미스터리 --narrative "$S/seoyeon_narratives.json#콩이" --story $S/mystery.txt \
          --author 윤서연 -p seoyeon --copy-to ../../shots/stage7-book-mystery

# 실제 프로필: 이야기를 Claude 로 쓰고 바로 책으로 (service.make_book)
VIRTUEME_DATA=/tmp/virtueme-stage6 uv run virtueme -p seoyeon book 러닝 --genre 1 --author 윤서연
```

- `--narrative` 는 서사 오브젝트 JSON 이나 `/query` 응답 전체를 받습니다. 예시 묶음 파일은 `경로#키` 로 고릅니다.
- `--story` 는 `/story` 출력 형식(첫 줄 `TITLE: 제목`, 빈 줄, 단락)이나 그냥 단락 글입니다. `<em ref>` 앵커는 벗겨서 씁니다.
- `--variant N` 은 같은 이야기로 다른 디자인을 뽑습니다. `--temperature T` 는 뽑기 온도입니다(기본 1.2, 0 이면 가장 흔한 값).
- `--set archetype=framed --set typeface=serif` 처럼 사람이 값을 덮어쓸 수 있습니다. 통제 어휘 밖의 값은 거부합니다.
- `--bleed 3` 은 사방 3mm 재단 여백을 붙인 PDF 를 만듭니다. 그림과 바탕색은 재단 여백 끝까지, 글자는 재단선 안에 둡니다.
- `--offline` 은 네트워크 없이 절차적 그림과 본문에서 뽑은 소개글로 만듭니다. `--fresh` 는 같은 프롬프트로 그린 그림이
  있어도 새로 그립니다.
- `references.json`·`grammar.json` 은 저장소에 들어 있으므로, 새로 책을 만들 때는 `collect`·`annotate` 를 다시 돌릴 필요가
  없습니다. 표지 그림에 참고 표지 이미지를 넘기려면 이미지가 `$VIRTUEME_DATA/book_refs/img/` 나 `core/data/book_refs/img/`
  가운데 한 곳에 있어야 합니다(없으면 참고 이미지 없이 그립니다).

코드에서 쓰는 함수는 두 개입니다. CLI·API 연결은 이 둘을 부르면 됩니다.

| 함수 | 하는 일 |
|---|---|
| `book.brief(genre, narrative_object=None, story_text=None, overrides=None, temperature=1.2, variant=0)` | 네트워크 없이 디자인 브리프(dict). 장 나누기와 장마다 삽화 프롬프트 포함 |
| `book.make_book(genre, story_text, title=None, author="나", narrative_object=None, profile="default", offline=False, temperature=1.2, variant=0, bleed_mm=0)` | 브리프 + 그림 + 소개글 + PNG·PDF, 반환값은 `brief.json` 내용과 파일 경로 |

`genre` 는 Storyseed 장르 번호(0 미스터리 ~ 5 코미디, 6 문학·에세이), 한국어 이름, 영문 키 가운데 무엇이든 됩니다.

그래서 비전 모델에게 장르도 따로 짐작하게 하고(아래 표의 "장르 일치"), 검색할 때 둘이 같으면 가산점을 줍니다.

## 라벨 검수

`review` 는 아직 검수하지 않은 표지를 장르마다 고르게 N 장 골라(시드 고정) 연락 시트 HTML 을 만듭니다
(`$VIRTUEME_DATA/book_refs/review/review-<시드>.html`). 표지 이미지 옆에 칸마다 선택 상자가 있어 틀린 칸만 바꾸면 되고,
"고친 값 내려받기"를 누르면 시트의 표지 전부가 JSON 하나로 내려옵니다. 바꾸지 않은 표지는 "맞음"으로 기록됩니다.
`review --apply` 로 넣으면 `references.json` 의 그 표지에 `label_checked: true`, 검수자·날짜, 고치기 전 모델 라벨
(`label_model`), 바꾼 칸(`label_corrected_fields`)이 남습니다. `review --stats` 는 지금까지의 일치율을 셉니다.

검수한 라벨은 세 곳에서 우선합니다. `grammar` 는 검수한 표지를 2배로 세고, 브리프의 참고 표지 검색은 검수한 표지에 0.1 을
더하고, `annotate` 를 다시 돌려도 검수한 라벨은 덮어쓰지 않습니다.

2026-10-03 에 장르마다 4~5장씩 30장(시드 1)을 이미지를 보며 검수했습니다. 모델 라벨이 사람 판단과 같은 비율은 다음과 같습니다.

| 칸 | 일치 | 주로 틀린 곳 |
|---|---|---|
| 레이아웃 원형 | 77% (23/30) | 무늬 없는 단색 바탕 가운데 그림을 `pattern`·`framed`·`split` 으로 봄 (4장), 종이 카드 위 그림을 `pattern` 으로 봄 (2장) |
| 제목 위치 | 90% (27/30) | 세로쓰기 한국어 제목, 표지 위쪽 절반을 차지하는 제목 |
| 제목 크기 | 83% (25/30) | 폭을 거의 다 채우는 제목을 `medium` 으로 낮춰 봄 |
| 서체 계열 | 80% (24/30) | 한국어 붓글씨 제목을 `sans`·`display` 로, 트라얀 계열 대문자를 `sans` 로 봄 |

| 장르 추정 | 97% (29/30) | |
| 다섯 디자인 칸이 모두 맞음 | 37% (11/30) | |

이전 판에서 무작위 12장을 본 결과(원형 10장, 제목 위치 9장)와 비슷한 수준입니다. 칸마다 열에 두셋은 틀리므로, 표지 한 장의
라벨보다 장르 단위 분포를 믿는 편이 안전합니다. 분위기는 판단 기준을 세우지 않아 검수하지 않았습니다.

## 브리프: 기록이 디자인 값이 되는 길

분위기는 장르 기본값에 서사 오브젝트를 더해 정합니다(`briefing.target_moods`).

| 입력 | 분위기 |
|---|---|
| 장르 (가중치 1.0) | 미스터리 mysterious, 로맨스 romantic, SF eerie, 판타지 dreamy, 스릴러 tense, 코미디 playful, 문학 serene |
| 정서 평균 `emotion.mean` (0.8) | 0.25 이상 warm, 0.1 이상 hopeful, -0.2 이하 melancholic, -0.45 이하 dark |
| 근거 기간 평균 각성도 (0.8) | 0.55 이상 energetic, 0.3 이하 serene |
| 비주얼 신호 (0.8) | conflict 0.5↑ tense, uncertainty 0.55↑ mysterious, novelty 0.6↑ whimsical, stability 0.75↑ serene, activity 0.6↑ energetic, possibility 0.62↑ hopeful · 0.38↓ nostalgic |
| 이야기 본문 (최대 0.5) | 감정 낱말(웃음·설렘·비밀·그리움·달리기 등) 수 |

참고 표지 점수는 같은 장르 1.0(비전 모델도 그 장르로 보면 +0.25, 다른 장르인데 그 장르로 보이면 0.35) + 분위기가 겹친
가중치 비율 + 톤 맞춤 0.2(정서가 밝으면 밝은 표지, 어두우면 어두운 표지) + 사람이 검수한 표지 0.1 입니다. 상위 6장을 씁니다.

### 값은 가장 흔한 것을 고르지 않고 분포에서 뽑습니다

칸마다 점수는 "장르 분포 × 0.5 + 6장의 점수 가중 표 × 0.5" 입니다. 이전 판은 점수가 가장 큰 값을 골랐고, 장르마다 전면 그림이
50~72%라 시험한 책이 모두 `full_bleed` 였습니다. 지금은 이 점수에서 p ∝ 점수^(1/T) 로 뽑습니다.

- 시드는 브리프 번호와 칸 이름입니다. 브리프 번호는 장르·분위기·서사 오브젝트 번호·이야기 본문·참고 표지·덮어쓴 값·온도·
  `variant` 의 해시라, 같은 입력으로 다시 렌더하면 같은 디자인이 나옵니다. `variant` 를 바꾸면 다른 디자인을 뽑습니다.
- 뽑은 확률은 `brief.json` 의 `decision.<칸>.probabilities` 에, 온도와 규칙은 `draw` 에 남습니다.
- 원형과 맞지 않는 값(그림 없는 원형의 그림 양식, 가운데 그림이 있는 원형의 가운데 제목)은 후보에서 뺍니다.
- 삽화는 표지와 같은 그림 양식으로 그립니다. 글자형 표지면 장르 분포에서 사진을 빼고 뽑습니다.

`러닝` 서사 오브젝트로 장르마다 `variant` 0~39 를 뽑은 결과(280권)입니다.

| 온도 | full_bleed | split | centered_motif | framed | pattern | typographic |
|---|---|---|---|---|---|---|
| 0 (이전 판과 같음) | 280 | 0 | 0 | 0 | 0 | 0 |
| 1.0 (점수 비례) | 165 | 35 | 56 | 19 | 3 | 2 |
| **1.2 (기본값)** | **140** | **61** | **50** | **16** | **12** | **1** |

기본값에서도 장르 성격은 남습니다. 스릴러·SF 는 40권 가운데 29·31권이 전면 그림이고, 코미디는 액자 10·전면 9·나눔 9·무늬 8·
가운데 그림 4권으로 가장 고르게 나옵니다. 글자형은 참고 표지 206장 가운데 몇 장뿐이라 거의 나오지 않습니다. 필요하면
`--set archetype=typographic` 으로 고릅니다.

### 팔레트

팔레트는 6장의 주요 색과 장르 팔레트를 CIELAB 에서 다시 묶은 5색을 정서 쪽으로 옮긴 것입니다. 정서가 v 만큼 명도 +8v,
색상각은 밝으면 따뜻한 쪽(60°), 어두우면 차가운 쪽(250°)으로 최대 |v|×20°, 채도는 × (0.8 + 0.5 × 각성도)입니다.
바탕·글자·강조색은 WCAG 대비로 고릅니다(글자 4.5 이상). 정서 곡선 자체는 장 시작 면과 뒤표지, 글자형 표지의 선으로 그립니다.

## 책 한 권의 구성

| 쪽 | 내용 |
|---|---|
| 앞표지 | 레이아웃 원형 여섯 가지마다 틀이 하나씩. 아래 「표지 틀」 |
| 1 속표지 | 장르 표시, 제목(표지와 같은 서체), 지은이, 버추얼미 |
| 2 | 빈 쪽 |
| 3 차례 | 장 번호, 장 제목, 시작 쪽 (쪽 번호는 다 앉힌 뒤 채움) |
| 4 | 빈 쪽 |
| 5~ 본문 | 장마다 새 쪽에서 시작하는 장 시작 면(장 번호, 장 제목, 정서 곡선 가운데 이 장에 해당하는 구간을 진하게)과 본문. 장마다 삽화 한 장 |
| 판권 | 왼쪽(짝수) 쪽. 속 쪽 수가 4의 배수가 되게 앞에 빈 쪽을 채웁니다. "버추얼미 · 기록에서 지은 이야기", 만든 날, 장르, 표지가 어디서 왔는지, 그림 모델, 판형, "개인 기록을 바탕으로 생성한 이야기이며 사건과 대사는 지어낸 것" 이라는 안내 |
| 뒤표지 | 소개글, 이야기 전체의 정서 곡선, 버추얼미 표시. 그림이 면을 채우는 원형(전면·나눔·무늬)은 표지 그림 아랫부분을 띠로 깝니다 |

**장 나누기** (`chapters.split_chapters`, 결정적): 장면 구분 줄(`***`, `* * *`, `---`, `#`, `◇` 등)이 있으면 그 자리에서
자릅니다. 없으면 본문 글자 수로 장 수를 정합니다. 1,000자 미만이면 한 장, 그 이상이면 800자마다 한 장(2~5장)이고, 장마다
단락이 둘 이상입니다. 자르는 자리는 같은 길이로 나눈 목표 지점에 가까운 단락 경계이며, 다음 단락이 "다음 날"·"그날 밤"·
"8월" 같은 전환 말로 시작하면 가산점을, 대사로 시작하면 감점을 줍니다. 지금 `/story` 프롬프트(8~12단락)로 쓴 이야기는
1,300자 안팎이라 두 장이 되고, 2,000자가 넘는 이야기는 세 장이 됩니다.

**장 제목과 소개글**: 키가 있으면 `google/gemini-2.5-flash` 를 한 번 불러 장 제목과 뒤표지 소개글(두세 문장, 결말을 밝히지
않음)을 받습니다. 이 요청은 `outbound` 로그에 "책 뒤표지 소개글" 로 남고, 결과는 책 폴더의 `blurb.json` 에 본문 해시와 함께
캐시합니다. 모델이 지시를 어기고 붙이는 "과연 ~일까?" 마지막 문장은 떼어 냅니다. 키가 없거나 실패하면 장 제목은 장 안의
짧은 비대사 단락(예: "루프였다"), 없으면 첫 문장을 18자 안에서 자른 것을 쓰고, 소개글은 첫 장에서 대사가 아닌 문장을
150자까지 이어 씁니다.

**삽화 자리**: 장 가운데 절반의 묘사 단락 가운데 가장 긴 것 뒤에 넣습니다. 높이 62mm 가 안 들어가면 54·46mm 로 줄여 보고,
그래도 안 들어가면 그 장을 지우고 그 쪽 글 맨 앞에 그림을 두고 다시 앉힙니다. 장이 한두 쪽뿐일 때 그림이 다음 쪽으로 밀려
장 끝 쪽에 그림과 한두 줄만 남던 일을 막으려는 것입니다. 렌더 보고서의 `figure_pages` 에 `moved_to_page_top` 으로 남습니다.

**펼침면 고르기**: 두 쪽 모두 글이 60% 넘게 찬 펼침면 가운데 둘째 장(없으면 첫째 장) 삽화가 든 것을 고릅니다. 없으면 25%로
낮춥니다. 빈 쪽·판권·이야기가 왼쪽 쪽에서 끝나 오른쪽이 빈 펼침면은 고르지 않습니다. 본문이 두 쪽 남짓이라 그런 펼침면이
하나도 없으면 글이 든 첫 두 쪽을 나란히 놓고 `spread_note` 에 그렇게 적습니다.

### 표지 틀

여섯 원형을 미스터리·로맨스 두 장르로 그려 보고 고쳤습니다.

| 원형 | 틀 |
|---|---|
| `full_bleed` | 그림이 전면, 제목은 정한 높이에 왼쪽 맞춤 |
| `framed` | 바탕색 위 100mm 정사각 그림과 2.4mm 띄운 0.5pt 테두리, 제목은 가운데 맞춤으로 그림 위나 아래 |
| `split` | 위(또는 아래) 44% 색면에 제목과 강조색 짧은 띠, 나머지 56%는 그림. 버추얼미 표시는 색면 안 오른쪽 |
| `pattern` | 무늬 그림이 전면, 가운데 바탕색 상자(이중 테두리) 안에 제목 |
| `centered_motif` | 바탕색 가운데 86mm 원 안에 그림, 가장자리를 둥글게 지움 |
| `typographic` | 큰 제목, 아래 36%는 강조색 면에 바탕색 선으로 정서 곡선 |

고친 것: 글자형 표지에서 제목이 길면 지은이가 색면에 겹치던 것(제목 최대 높이를 정하고 색면 위로 막음), 무늬형 제목이
24pt 까지 작아지던 것, 가운데 그림형에서 모델이 작은 그림을 넓은 다른 색 바탕에 그려 원 안에 회색 원이 생기던 것(그림이
틀의 2/3 를 채우고 바탕을 팔레트 바탕색으로 칠하라고 지시하고 원 가장자리를 흐리게 지움).

그림은 OpenRouter `google/gemini-3.1-flash-image-preview`(1K)로 그립니다. 표지는 2:3(전면·무늬·나눔) 또는 1:1, 삽화는 3:2 입니다.

- 표지 그림에는 브리프의 참고 표지 가운데 그림 양식이 같은 것 3장을 스타일 참고로 넘깁니다.
- 장마다 삽화 한 장(최대 4장)을 그립니다. 삽화에는 방금 그린 표지 그림을 "같은 화가의 연작" 참고로 넘겨 매체·선·색·빛을
  맞추고, 구도와 대상은 따라 하지 말라고 합니다. 삽화는 병렬로 그립니다.
- 프롬프트에 글자·의성어·글자가 실리는 물건(화면·간판·번호판)을 그리지 말라고 넣고, 받은 그림은 비전 모델이 읽을 수 있는
  글자가 있는지 다시 봅니다. 있으면 두 번까지 다시 그립니다. 이번 시험에서 새로 그린 21장 가운데 7장이 걸렸습니다
  (신발의 ASICS 로고, 편의점 간판, 잠자는 강아지 위의 "zzz", 책장 속 글씨 등).
- 전면 그림 표지는 그림이 가로로 곧게 갈려 한쪽이 빈 띠로 남았는지(`art.hard_band`)도 재서 다시 그립니다. 하늘과 바다가
  만나는 수평선처럼 양쪽에 결이 있는 경계는 걸리지 않게 표지 11장으로 기준을 맞췄습니다.
- 표지가 AI 그림인 책에서 삽화가 끝내 실패하면, 그림체가 어긋나지 않게 절차적 그림으로 바꾸지 않고 그 장은 삽화 없이 갑니다.
  키가 없을 때만 팔레트와 정서 곡선으로 그린 절차적 그림을 씁니다(시드가 브리프 번호라 같은 브리프면 같은 그림).
- 같은 프롬프트로 그린 AI 그림은 `art_cache.json` 으로 알아보고 다시 사지 않습니다.

결과 폴더 `$VIRTUEME_DATA/books/<프로필>/<브리프 번호>/` 에는 `brief.json`, `cover_art.png`, `illustration-<장>.png`,
`blurb.json`, `book.html`, 위 PNG 여덟 장, `book.pdf` 가 남습니다. 그림 요청은 다른 요청처럼 `outbound` 로그에
"책 cover_art 그림 생성", "책 illustration-2 그림 생성", "그림 속 글자 검사" 용도로 남습니다(이미지는 로그에 넣지 않고 장 수와
참고 표지 번호만).

- "배운 것"은 206장의 분포입니다. 장르마다 28~30장이라 한두 장이 비율을 3~4%포인트 움직이고, 라벨은 30장만 사람이 봤습니다.
  검수한 30장에서 다섯 디자인 칸이 모두 맞은 표지는 37%뿐입니다.
- 원서 표지가 절반이고 Open Library 주제어가 거칠어 장르 일치가 40~96%로 들쭉날쭉합니다. 국내 출판사 표지를 더 모으려면
  알라딘·국립중앙도서관 API 키가 필요합니다.
- 글자형 원형은 참고 표지에 몇 장뿐이라 뽑기로는 거의 나오지 않습니다.
- 지금 `/story` 프롬프트는 8~12단락이라 대부분 두 장짜리 얇은 책(속 12쪽)이 됩니다. 세 장 넘는 책을 만들려면 더 긴 이야기나
  여러 편을 묶는 입력이 필요합니다.
- 장이 한 쪽 남짓이면 삽화가 장 시작 면 글 맨 앞으로 올라가는 일이 잦습니다. 그러면 펼침면 PNG 는 앞 장의 끝 쪽(덜 찬 쪽)과
  다음 장 시작 면이 됩니다.
- 이미지 모델이 표지 그림 테두리에 자기 종이 여백이나 선을 그려 넣는 일이 있습니다(코미디 예시의 삽화 양옆 세로선).
  지금은 검사하지 않습니다.
- 뒤표지 띠는 표지 그림 아랫부분을 잘라 쓰므로 인물의 몸통만 걸리는 경우가 있습니다(미스터리 예시).
- 한국어 본문은 어절 단위로 줄을 바꾸고 양끝을 맞추므로 어절 사이가 벌어지는 줄이 있습니다. 브라우저가 글자 사이 맞춤
  (`text-justify: inter-character`)을 지원하지 않아 자간을 1.5% 좁히는 데서 멈췄습니다.
- 재단 여백은 그림과 바탕만 늘리고 재단선 표시(크롭 마크)는 넣지 않습니다. 인쇄소가 요구하면 따로 넣어야 합니다.
